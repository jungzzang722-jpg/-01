# 인물 분리와 랜드마크 — 옷이 엉뚱한 자리에 붙던 이유

사용자가 결과를 보고 한 말은 이것이었습니다.

> "이건 뭐 찢어진 천을 붙힌 수준인데?"

옷을 그리는 코드도, 색을 바꾸는 코드도 아니었습니다. **몸을 잘못 읽고
있었습니다.** 옷을 아무리 잘 그려도 어깨가 배 위에 있다고 믿으면 결과는
찢어진 천이 됩니다.

이 문서는 그 아래를 고친 기록입니다. 두 층입니다.

1. **인물 분리** — 사진에서 사람과 배경을 가른다
2. **랜드마크** — 그 실루엣에서 어깨·가슴·허리·골반·가랑이를 찾는다

---

## 1. 인물 분리 — 배경의 분산으로 임계를 정한다

### 옛 방식이 무너지던 곳

진단용 마스크(`BODY.personMask`)는 640px에서 만들어집니다. 피팅은 900px에서
합성하므로 그 마스크를 **늘려 썼습니다**. 두 가지가 따라옵니다.

- 경계가 계단이 된다 (늘린 만큼 그대로)
- 640px에서 놓친 구멍을 그대로 물려받는다

그리고 임계값을 전역 Otsu로 잡았습니다. Otsu는 히스토그램이 두 봉우리일 때
그 사이를 가릅니다. 그런데 전신 사진은 **배경이 압도적으로 많습니다.**
봉우리 하나가 거대하면 Otsu는 임계를 그쪽으로 끌어당깁니다. 옷과 배경 색이
비슷하면(흰 셔츠 + 흰 벽) 옷이 통째로 배경으로 빠집니다.

### 새 방식

합성할 해상도에서 직접 나눕니다(`build/segment.js`). 그리고 임계는
**배경 자신의 산포**에서 정합니다.

```js
// 가장자리 띠에서 행별 배경색을 세우고, 각 픽셀이 그 배경에서
// 얼마나 떨어졌는지(dist)를 잰다
bd.sort(function (a, b) { return a - b; });
var spread = bd[Math.floor(bd.length * 0.985)];   // 배경 자신의 흔들림
var thr = clamp(spread * 1.35, 2.2, 30);
```

배경이 매끄러우면 임계가 낮아져 미세한 차이도 인물로 잡고, 배경이 어수선하면
임계가 높아져 잡티를 걸러냅니다. **인물이 얼마나 큰지, 옷이 무슨 색인지에
의존하지 않습니다.** Otsu가 무너지던 지점이 정확히 여기였습니다.

### 순서가 결과를 갈랐다

```
raw → 열림(잡티 제거) → dropSpecks → fillHoles
    → bridgeColumns → fillHoles → largestBlob → fillHoles
```

`largestBlob`(가장 큰 덩어리만 남기기)을 **구멍 메우기보다 먼저** 두었더니
흰 셔츠가 배경으로 빠진 사진에서 머리·팔·바지가 각각 섬이 되어 전부
버려졌습니다. 구멍을 먼저 메워 하나로 이은 다음 가장 큰 덩어리를 골라야
합니다.

`bridgeColumns`(세로로 끊긴 곳 잇기)도 무조건 이으면 안 됩니다. 쉬운 사진에서
1.4%를 깎아먹었습니다. **위아래가 서로 다른 연결요소일 때만** 잇습니다 —
같은 요소면 이미 이어져 있으므로 이을 이유가 없습니다.

```js
if (prev >= 0 && y - prev > 1 && y - prev <= maxGap &&
    lab[prev * w + x] !== lab[y * w + x]) {
  for (var k = prev + 1; k < y; k++) { out[k * w + x] = 1; }
}
```

### 결과 (정답 실루엣 대비 IoU · 1.0이 완벽)

| 조건 | 옛 방식 | 새 방식 |
|---|---|---|
| 어두운 옷 · 밝은 벽 (쉬움) | 0.982 | 0.983 |
| 흰 옷 · 흰 벽 | 0.325 | **0.863** |
| 베이지 옷 · 베이지 벽 | 0.171 | **0.874** |
| 어두운 옷 · 어두운 벽 | 0.221 | **0.983** |

45벌 × 3체형 = 129회 합성에서 **덮인 면적이 비정상적으로 적은 사례가
6건 → 0건**이 되었습니다.

## 2. 랜드마크 — 얼굴을 거치지 않는다

### 얼굴에서 출발하면 반팔에서 무너진다

`body.js`의 어깨·허리·골반은 **얼굴 박스에서 역산**합니다. 얼굴 박스는
피부색 규칙으로 찾습니다. 그런데 반팔을 입으면 **두 팔이 얼굴보다 큰 살색
덩어리**가 됩니다. 팔을 얼굴로 잡으면 턱이 배까지 내려가고 어깨가 허리
아래로 갑니다.

실측값입니다.

| | 어깨 | 허리 | 골반 |
|---|---|---|---|
| 얼굴 기반 | 440 | 284 | 419 |
| 정답 | 174 | 402 | 474 |

순서 보정(`saneLM`)은 순서만 바로잡을 뿐 값 자체가 틀린 것은 고치지
못합니다. "찢어진 천"의 정체가 이것이었습니다.

### 실루엣 폭 프로파일에서 직접 읽는다

서 있는 전신 사진에서 폭은 이렇게 변합니다.

```
정수리 → (머리, 좁음) → 목(최소) → 어깨(급격히 넓어짐)
       → 허리(다시 좁아짐) → 골반(넓어짐) → 가랑이(둘로 갈라짐)
```

이 변화는 얼굴을 찾지 않아도 읽힙니다. 피부색·조명·머리 길이에 흔들리지도
않습니다(`silhouetteLM`).

**가랑이는 아래에서 위로 찾습니다.** 위에서 내려가며 "처음 둘로 갈라지는
행"을 찾으면 팔이 몸에서 떨어진 행에 걸립니다 — 골반이 314(정답 474)로
나온 원인이었습니다. 발목 쪽은 반드시 두 조각이므로 거기서 올라오며 하나로
합쳐지는 첫 지점을 잡으면 팔에 속지 않습니다.

**받아들이기 전에 검산합니다.** 저대비 사진에서 마스크가 조각나면 폭
프로파일이 의미를 잃습니다. 사람이라면 반드시 참인 범위(어깨는 위쪽 1/3
안에, 허리는 어깨 아래에, 어깨는 허리보다 넓게 …)를 확인하고, 하나라도
어긋나면 이 판독을 버리고 예전 값으로 돌아갑니다. **틀린 새 값보다 낡은
값이 낫습니다.**

## 3. 잘 분리하고 나니 드러난 것들

인물 분리가 좋아지자 **팔이 몸통과 한 덩어리로** 잡히기 시작했습니다.
예전에는 팔이 배경에 먹혀 저절로 빠져 있었던 것입니다. 그러자 "가장 긴
전경 구간"이 팔까지 삼켰고, 연쇄적으로 세 가지가 무너졌습니다.

### (가) 반팔 티셔츠가 판초가 됐다

몸통 폭을 실루엣에서 재니 팔 두께가 더해졌습니다. 그 폭으로 옷을
재단하면 티셔츠가 팔까지 덮습니다.

**반팔을 입은 사람은 팔이 맨살이고 몸통이 옷입니다.** 그러니 전경이면서
피부가 아닌 최장 구간을 재면 팔이 저절로 빠집니다. 긴팔이면 팔도 옷이라
함께 잡히는데, 그때는 긴팔이 팔을 덮는 것이 맞으므로 문제가 없습니다.

행마다 세 가지를 둡니다.

| | 뜻 |
|---|---|
| `x0/x1` | 실루엣 전체 (팔·손 포함) |
| `cx0/cx1` | 가장 긴 전경 구간 |
| `tx0/tx1` | 가장 긴 **옷 구간** (전경이면서 피부가 아닌 곳) |

다만 **어깨만은 실루엣**을 씁니다. 어깨선 높이에서는 팔이 아직 몸통 옆으로
내려오지 않아 실루엣이 곧 어깨 너비입니다. 반대로 민소매를 입으면 옷 구간은
어깨끈 폭이라 어깨가 실제의 2/3로 줄어듭니다 — 그 값으로 재킷을 재단하니
몸통 픽셀의 7%가 옷 밖으로 밀려났습니다.

### (나) 청바지가 팔뚝에 칠해졌다

허리·골반 폭을 "가장 긴 구간"에서 재니 팔이 포함됐고, 그 폭으로 잡은
대응점 사이를 TPS가 메우면서 데님이 팔에 발렸습니다.

폭은 `tx`로 고쳤고, 여기에 **몸 쪽 울타리**를 더했습니다. TPS는 대응점
바깥으로도 매끄럽게 이어지므로 허리 옆에 붙어 있는 팔뚝이 옷본 안쪽
좌표로 떨어질 수 있습니다. 울타리는 허리·골반 대응점이 만든 폭 그 자체입니다.

### (다) 소매가 팔꿈치에 벙어리장갑처럼 얹혔다

두 가지가 겹쳤습니다.

**소매 길이를 옷 기장에서 역산했습니다.** 옷본의 소맷부리 높이를
어깨~밑단에 선형 대응시키면, 밑단이 50px만 어긋나도 반팔 소매가 팔꿈치
아래까지 내려갑니다. 소매 길이는 옷의 기장이 아니라 **팔**이 정하는
값입니다. 어깨에서 손목까지를 1로 놓으면 사람마다 거의 같은 비율에
떨어집니다.

| 캡 | 반팔 | 7부 | 긴팔 |
|---|---|---|---|
| 0.12 | 0.28 | 0.75 | 1.0 |

위팔(어깨~팔꿈치)이 팔 전체의 약 0.48이므로 반팔 0.28은 위팔의 60% 지점 —
실제 반팔이 끝나는 곳입니다. 그리고 손목은 **재서** 씁니다: 실루엣이 한
조각이어도 옷 구간 바깥의 맨살을 따라가면 팔이 어디서 끝나는지 알 수
있습니다.

**소매가 갈 수 있는 자리를 몸 쪽에서 못박지 않았습니다.** 조각마다 TPS는
대응점 바깥으로도 이어지므로, 가슴 한복판의 픽셀이 옷본의 소매 안쪽
좌표로 떨어질 수 있습니다. 그러면 소매 밑단 솔기가 가슴에 **눈썹 모양
곡선 두 개**로 그려집니다 — 실제로 그렇게 나왔습니다. 소매는 어깨점 →
겨드랑이 → 소맷부리 안쪽을 잇는 선의 바깥쪽 띠에만 있을 수 있습니다.

## 4. 잰 값과 해부학 비율을 섞는 법

허리는 "가장 좁은 곳"입니다. 그런데 남성처럼 옆선이 밋밋하면 최솟값의
위치를 **픽셀 잡음이 정합니다.** 얕은 골을 믿고 40px 어긋난 적이 있습니다.
반대로 얕다고 버리면, 실제로 잘록한 사람의 정보를 통째로 버립니다.

그래서 **골의 깊이만큼만 믿습니다.**

```js
var depth = ref / smT[cand] - 1;          // 얼마나 들어가 있나
var trust = clamp(depth / 0.06, 0, 1);    // 6% 이상이면 그대로 쓴다
var waistY = anatW + (cand - anatW) * trust;
```

해부학 비율(`anatW`)은 신장 대비 어깨 0.182 · 허리 0.38 · 골반 0.47에서
나온 0.68입니다. 6% 이상 들어간 허리는 잰 값을 그대로 쓰고, 밋밋하면
비율 쪽으로 끌어당깁니다. **버리지도, 통째로 믿지도 않습니다.**

골반도 같은 성격입니다. "가랑이에서 일정 비율 위"로만 잡으면 다리가 긴
사람에게서 40px 넘게 내려갑니다. 그래서 가랑이 **바로 위** 좁은 창에서
옷 폭의 최댓값을 찾되, 창을 넓게 잡으면 상의 밑단이 들어와 그것을 골반으로
잡아 버립니다(엉덩이 블록이 무릎까지 늘어났습니다). 그리고 최댓값이 창의
**끝에 붙어 있으면** 쓰지 않습니다 — 그것은 "여기가 제일 넓다"가 아니라
"창 밖이 더 넓다"는 뜻이기 때문입니다.

## 5. 지금 상태

| 검증 | 결과 |
|---|---|
| 인물 분리 IoU (4개 조건) | 0.86 ~ 0.98 |
| 합성 실패 | 0건 / 129회 |
| 덮인 면적 부족 | 0건 / 129회 (이전 6건) |
| 중심선 매핑 뒤집힘 | 0회 |
| 페이지 오류 | 0건 |

### 여전히 못 하는 것

- **팔짱·주머니에 넣은 손.** 팔과 몸통이 색으로도 형태로도 나뉘지 않습니다.
- **피부색 상의.** 옷 구간을 피부로 판정해 몸통 폭을 잃습니다. 이때는
  실루엣 폭으로 되돌아가므로 팔이 포함된 예전 동작이 됩니다.
- **누운 자세·크게 기운 자세.** 폭 프로파일 가정 자체가 성립하지 않습니다.
  검산에서 걸러 예전 값으로 돌아갑니다.
- **배경이 인물과 같은 색이고 그 면적이 넓은 경우.** 배경 산포로 임계를
  잡아도 구분할 신호 자체가 없습니다.
