## 추천: CatVTON

졸업전시에는 **CatVTON**을 권합니다.

- **VRAM 8GB 미만** — RTX 3060 12GB, 4060 Ti 같은 소비자용 GPU에서 돕니다.
  전시장에 A100을 가져갈 수는 없습니다.
- 전체 파라미터 899M으로 가벼워 설치와 기동이 빠릅니다.
- 라이선스가 다른 후보와 같은 조건입니다(어차피 다 비상업).

---

## 구성

```
브라우저 (고화질판 HTML)
    │  배경 지운 인물 + 옷 이미지
    ▼
중계 서버   server/vton-proxy.mjs      Node 18+, 의존성 없음
    │  한도 확인 · 겹쳐 입기 순서 관리
    ▼
모델 서버   server/model/vton_server.py   Python, GPU
```

중계와 모델을 나눈 이유: 모델 서버는 GPU에 묶여 무겁게 뜨고, 중계는 가볍게
자주 고칩니다. 한도·CORS·오류 문구를 고치자고 모델을 다시 올릴 이유가 없습니다.

## 순서 — 모델보다 배선을 먼저

**GPU 없이도 전체가 도는지 먼저 확인하세요.** 이 순서를 지키면 나중에 문제가
생겼을 때 "배선은 이미 됐었다"는 사실이 원인을 절반으로 좁혀 줍니다.

### 1단계 — 모의 모드로 배선 확인 (지금 바로 됨)

```bash
cd ~/pcolor
./server/start.sh
```

서버 두 개를 올바른 설정으로 함께 띄우고, 포트를 물고 있던 옛 서버를
정리하고, `doctor` 까지 돌려 상태를 보여줍니다. **Ctrl+C 한 번에 둘 다** 꺼집니다.

전시 당일에 환경변수 이름을 외우고 있어야 하는 프로그램은 전시 당일에 안
돌아가는 프로그램이므로, 손으로 칠 일을 한 줄로 줄였습니다. 손으로 띄우실
때의 설정은 `start.sh` 안에 그대로 적혀 있습니다.

`퍼스널컬러진단_고화질합성.html` 을 열고 피팅 탭 맨 아래 카드에
`http://localhost:8787` 입력 → 동의 → "고화질로 합성".

**빨간 `MOCK` 띠가 그려진 인물 사진이 그대로 돌아오면 배선은 끝난 것입니다.**
띠를 그리는 이유는, 예전에 이걸 안 그렸다가 모의 결과를 합성 실패로 오해해
멀쩡한 배선을 의심하며 한참을 헤맸기 때문입니다. 자동 검증도 있습니다:

```bash
node build/test-selfhost.mjs
```

### 2단계 — CatVTON 설치

```bash
git clone https://github.com/Zheng-Chong/CatVTON.git ~/CatVTON
cd ~/CatVTON
python3 -m venv .venv && source .venv/bin/activate
pip install --upgrade pip
pip install torch torchvision
pip install "diffusers==0.29.2" "huggingface_hub<0.26" transformers accelerate \
            pillow numpy scipy scikit-image opencv-python
python3 -c "import torch; print(torch.backends.mps.is_available())"   # 맥이면 True
```

**저장소의 `requirements.txt` 를 그대로 쓰면 맥에서 실패합니다.**
`xformers` 가 들어 있는데 NVIDIA 전용이라 애플 실리콘에서는 설치 자체가
안 되고, 없어도 CatVTON 은 돕니다(속도만 조금 느려집니다). 핀으로 박힌
`torch==2.1.2` 도 mps 지원이 불안정하던 시절 버전이라 최신을 쓰는 편이
낫습니다. `gradio` 는 저장소 자체 데모 화면용이라 우리에게는 필요 없습니다.
`diffusers` 만 버전을 고정하는 이유는 CatVTON 코드가 그 시점 API 를 쓰기
때문입니다.

**미리 알아둘 것 셋** (모르면 각각 한 시간씩 잡아먹습니다)

1. **`model.*` 과 `utils` 임포트는 저장소 기준 경로입니다.**
   서버를 저장소 밖에서 실행하면 `ModuleNotFoundError` 가 납니다.
   `VTON_REPO_DIR` 로 위치를 알려주면 서버가 `sys.path` 에 넣어 줍니다.

2. **Detectron2 와 DensePose 는 설치하지 않아도 됩니다.**
   옷이 놓일 자리 마스크는 **브라우저가 만들어 함께 보냅니다.** 원래 그
   마스크를 만드는 AutoMasker 가 설치 용량과 실패의 대부분이었고, 애플
   실리콘에서는 GPU 가속조차 안 되는 부분이었습니다. 굳이 쓰시려면
   `VTON_AUTOMASK=1` 로 켤 수 있게 남겨 두었습니다.

3. **가중치는 처음 실행할 때 자동으로 내려받습니다** (`zhengchong/CatVTON`,
   `runwayml/stable-diffusion-inpainting`). 수 GB 이므로 **전시장 와이파이가
   아니라 미리** 받아 두세요.

### 3단계 — 실제 모델로 켜기

```bash
cd ~/pcolor
source ~/CatVTON/.venv/bin/activate
VTON_REPO_DIR=~/CatVTON ./server/start.sh real
```

`장치 mps · 정밀도 fp16` 과 `모델 적재됨` 이 나와야 합니다.
**장치는 서버가 스스로 고릅니다** — mps(애플 실리콘) → cuda → cpu 순.
기본값을 cuda 로 두면 맥에서는 무조건 실패하는데, 사용자가 `VTON_DEVICE`
라는 이름을 알아야만 돌아가는 프로그램은 전시 당일에 안 돌아갑니다.

한 벌 합성에 맥에서 **30초~2분**입니다. 0.8초에 끝났다면 그건 모의 결과입니다.

**맥에서는 해상도가 384×512, 단계는 20 입니다** (그 외 장치는 768×1024 / 30).
CatVTON 은 인물과 옷을 이어 붙여 어텐션을 계산해서 토큰이 두 배가 되고,
어텐션 행렬은 토큰 수의 제곱으로 자란다 — 768×1024 에서는 그 행렬 하나가
18GB 라 `Invalid buffer size: 18.00 GiB` 로 죽는다. NVIDIA 쪽은 xformers 가
쪼개 주지만 맥에는 xformers 가 없다. 그래도 부족하면 더 낮춘다:

```bash
VTON_WIDTH=320 VTON_HEIGHT=448 VTON_REPO_DIR=~/CatVTON ./server/start.sh real
```

반대로 메모리가 넉넉한 맥(64GB 이상)이라면 올려서 화질을 얻을 수 있다:

```bash
VTON_WIDTH=576 VTON_HEIGHT=768 VTON_REPO_DIR=~/CatVTON ./server/start.sh real
```

**`height`/`width` 를 파이프라인에 반드시 넘길 것.** 안 넘기면
`CatVTONPipeline.__call__` 이 자기 기본값(1024×768)을 쓰고, `check_inputs` 가
줄여 보낸 이미지를 그 크기로 **도로 늘린다.** 이미지만 작게 만들어 넘기던
동안에는 아무리 줄여도 18GB 가 그대로였다 — 두 번의 OOM 을 이것으로 낭비했다.

요구량은 서버 창에 찍힌다:

```
  384x512 · 20단계 · 토큰 6144 · 어텐션 1.1GiB
```

토큰은 `(W/8)×(H/8)` 의 두 배(인물+옷을 이어 붙이므로), 어텐션은 그 제곱이다.
줄였는데 숫자가 그대로면 설정이 안 먹은 것이다.

| 해상도 | 어텐션 | 16GB 맥 |
|---|---|---|
| 768×1024 | 18.0 GiB | ✗ |
| 576×768 | 5.7 GiB | △ |
| 384×512 | 1.1 GiB | ✓ |

**어텐션 분할(`set_attention_slice`)로 메모리를 줄이려 하지 말 것.**
diffusers 가 그것을 켤 때 UNet 의 어텐션 처리기를 표준 처리기로 갈아 끼우는데,
CatVTON 은 텍스트 조건을 일부러 없앤 `SkipAttnProcessor` 를 쓴다. 그게 덮이면
없는 텍스트 경로가 되살아나 `(24576x320 and 768x320)` 로 죽는다(768 은 CLIP
텍스트 임베딩 차원이다). 한 번 켜 봤다가 이 오류를 만났다.

**모델 적재에 실패해도 서버는 뜹니다.** 일부러 그렇게 했습니다 — 서버가 아예
안 뜨면 무엇이 잘못됐는지 확인할 창구조차 없어집니다. 그때 합성 요청에는
이유를 담아 응답하고, 앱은 내장 엔진으로 되돌아갑니다.
무엇이 막혔는지는 언제나 이걸로 가릅니다:

```bash
node server/doctor.mjs
```

브라우저는 중계 문제·모델 문제·CORS 문제에 **똑같은 에러**를 보여주기
때문에, 층을 나눠 짚어 주는 도구가 따로 필요합니다.

### 코드는 이미 채워져 있습니다

`load_model()` 과 `run_model()` 은 CatVTON 의 `app.py` 를 그대로 따라 채웠습니다.

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `VTON_REPO_DIR` | — | CatVTON 저장소 위치 **(필수)** |
| `VTON_REPO` | `zhengchong/CatVTON` | 가중치 저장소 |
| `VTON_BASE` | `runwayml/stable-diffusion-inpainting` | 베이스 모델 |
| `VTON_PRECISION` | `bf16` | 8GB VRAM 은 이 값 기준 |
| `VTON_WIDTH` / `VTON_HEIGHT` | 768 / 1024 | 학습 해상도 |
| `VTON_STEPS` | 30 | 낮추면 빨라지고 거칠어집니다 |
| `VTON_GUIDANCE` | 2.5 | |
| `VTON_SEED` | 555 | −1 이면 매번 다르게 |

`run_model()` 이 처리하는 것 셋 — 그냥 넣으면 결과가 나빠지는 것들입니다.

1. **투명 배경을 흰색으로 채웁니다.** 우리가 보내는 인물은 배경이 이미
   지워져 있는데, 모델은 배경 있는 사진으로 학습돼 있어 알파가 검정으로
   해석되면 결과가 무너집니다.
2. **인물은 잘라 맞추고(crop) 옷은 여백을 채워 맞춥니다(padding).**
   반대로 하면 옷이 잘려 나갑니다.
3. **마스크 가장자리를 흐립니다**(blur_factor=9). 안 흐리면 옷과 피부의
   경계에 딱딱한 선이 남습니다.

## 전시장 운영

### 하드웨어

- GPU 한 장이면 충분합니다. 관람객이 줄을 서므로 **동시 처리보다 안정성**이
  중요합니다. 모델 서버는 요청을 순서대로 처리하게 두세요.
- 인터넷이 필요 없습니다. **노트북 한 대 안에서 전부 돌 수 있습니다.**
  전시장 와이파이는 믿을 게 못 됩니다.

### 한도

전시에서는 한 사람이 여러 벌 보는 게 정상이므로 5벌은 너무 적습니다.

```bash
VTON_QUOTA_PER_DAY=50 VTON_QUOTA_PER_IP_DAY=500 node server/vton-proxy.mjs
```

로컬 구동이면 장당 과금이 없으므로 한도의 목적이 "비용 방어"에서 "줄 관리"로
바뀝니다.

### 개인정보 — 전시는 훨씬 가볍습니다

노트북 안에서 전부 돌면 사진이 **어디로도 가지 않습니다.** 국외이전도, 위탁도
없습니다. 그래도 관람객의 얼굴을 다루므로 최소한 이건 하세요.

- 부스에 안내문: **무엇을 촬영하고 / 어디로 가고 / 언제 사라지는가**
- "이 기기 안에서만 처리되며 저장하지 않습니다" — 지금 구조가 실제로 그렇습니다
- 결과 이미지를 나눠 준다면 그 자리에서 주고 끝내세요. 모아 두지 마세요.
- 촬영 자체를 원치 않는 분을 위해 **미리 준비한 샘플 인물**로도 볼 수 있게
  해 두면 좋습니다.

`docs/11` 의 처리방침 초안에서 "국외이전" 항목을 빼면 그대로 쓸 수 있습니다.

### 실패에 대비

전시장에서 가장 흔한 사고는 **모델 서버가 죽는 것**입니다.

지금 구조는 그때 자동으로 내장 엔진 결과로 되돌아갑니다 — 화면이 비지 않고,
관람객은 무언가를 봅니다. 이게 이 설계의 실질적인 이득입니다.

리허설에서 **일부러 모델 서버를 꺼 보세요.** 그 상태에서도 앱이 정상으로
보이는지 확인하면 당일 마음이 편합니다.
