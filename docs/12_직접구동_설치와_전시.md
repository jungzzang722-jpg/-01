# 모델 직접 구동 — 설치와 졸업전시 운영

## 라이선스부터 (가장 중요)

공개된 주요 가상 피팅 모델은 **전부 CC BY-NC-SA 4.0 — 비상업 전용**입니다.

| 모델 | 라이선스 | VRAM | 상업 이용 |
|---|---|---|---|
| CatVTON | CC BY-NC-SA 4.0 | **8GB 미만** (1024×768) | ✗ |
| IDM-VTON | CC BY-NC-SA 4.0 | ~16GB | ✗ |
| OOTDiffusion | 비상업 조항 포함 | ~16GB | ✗ |
| Leffa | 저장소에서 직접 확인 필요 | 12GB (+RAM 32GB, 설치 20GB) | 확인 필요 |

**졸업전시는 비상업이므로 사용할 수 있습니다.** 다만 BY-NC-SA는 "돈만 안 받으면
끝"이 아닙니다.

- **BY (저작자 표시)** — 전시 패널·크레딧에 모델 이름과 저자를 적어야 합니다.
- **SA (동일조건변경허락)** — 파생물을 **배포**한다면 같은 라이선스여야 합니다.
- 관람객에게 결과 이미지를 나눠 준다면 출처 표기를 함께 두는 것이 안전합니다.

> 나중에 상용으로 전환하려면 저자와 **별도 계약**이 필요합니다. 지금 코드를
> 공급자 교체가 쉽게 짜 둔 이유가 이것입니다 — 그때 모델만 바꾸면 됩니다.

## 추천: CatVTON

졸업전시에는 **CatVTON**을 권합니다.

- **VRAM 8GB 미만** — RTX 3060 12GB, 4060 Ti 같은 소비자용 GPU에서 돕니다.
  전시장에 A100을 가져갈 수는 없습니다.
- 전체 파라미터 899M으로 가벼워 설치와 기동이 빠릅니다.
- 라이선스가 다른 후보와 같은 조건입니다(어차피 다 비상업).

## 구성

```
브라우저 (고화질판 HTML)
    │  배경 지운 인물 + 옷 이미지
    ▼
중계 서버   server/vton-proxy.mjs      Node 18+, 의존성 없음
    │  한도 확인 · 겹쳐 입기 순서 관리
    ▼
모델 서버   server/model/vton_server.py   Python, GPU
```

중계와 모델을 나눈 이유: 모델 서버는 GPU에 묶여 무겁게 뜨고, 중계는 가볍게
자주 고칩니다. 한도·CORS·오류 문구를 고치자고 모델을 다시 올릴 이유가 없습니다.

## 순서 — 모델보다 배선을 먼저

**GPU 없이도 전체가 도는지 먼저 확인하세요.** 이 순서를 지키면 나중에 문제가
생겼을 때 "배선은 이미 됐었다"는 사실이 원인을 절반으로 좁혀 줍니다.

### 1단계 — 모의 모드로 배선 확인 (지금 바로 됨)

```bash
# 터미널 1 — 모델 서버 (모의)
VTON_MODE=mock python3 server/model/vton_server.py

# 터미널 2 — 중계 서버
VTON_PROVIDER=custom VTON_ENDPOINT=http://localhost:8788/tryon \
VTON_QUOTA_PER_DAY=5 node server/vton-proxy.mjs
```

`퍼스널컬러진단_고화질합성.html` 을 열고 피팅 탭 맨 아래 카드에
`http://localhost:8787` 입력 → 동의 → "고화질로 합성".

인물 사진이 그대로 돌아오면 배선은 끝난 것입니다. 자동 검증도 있습니다:

```bash
node build/test-selfhost.mjs
```

### 2단계 — 모델 붙이기

```bash
git clone https://github.com/Zheng-Chong/CatVTON
# 저장소 README 의 설치 절차를 따릅니다 (torch, diffusers, 가중치 내려받기)
```

`server/model/vton_server.py` 의 **두 함수만** 채웁니다.

- `load_model()` — 한 번만 올립니다. 요청마다 올리면 매번 수십 초입니다.
- `run_model()` — 인물 PNG + 옷 PNG → 합성 PNG.

`run_model()` 주석에 적어둔 세 가지를 반드시 처리하세요.

1. **인물 이미지는 배경이 이미 지워져 있습니다.** 모델은 배경 있는 사진으로
   학습돼 있어서 투명 배경을 그대로 넣으면 결과가 나빠집니다. **흰색으로 채우세요.**
2. **마스크가 필요합니다.** 옷이 놓일 자리를 알려줘야 합니다. 사람 파싱 +
   자세 추정을 함께 돌립니다 — 설치 용량의 대부분이 이 전처리입니다.
3. **해상도.** 1024×768 같은 고정 비율로 학습돼 있습니다. 넣기 전에 맞추고
   나온 뒤 되돌리세요.

```bash
VTON_MODE=real python3 server/model/vton_server.py
```

아직 안 채웠으면 **501과 함께 무엇을 하면 되는지** 알려줍니다.

## 전시장 운영

### 하드웨어

- GPU 한 장이면 충분합니다. 관람객이 줄을 서므로 **동시 처리보다 안정성**이
  중요합니다. 모델 서버는 요청을 순서대로 처리하게 두세요.
- 인터넷이 필요 없습니다. **노트북 한 대 안에서 전부 돌 수 있습니다.**
  전시장 와이파이는 믿을 게 못 됩니다.

### 한도

전시에서는 한 사람이 여러 벌 보는 게 정상이므로 5벌은 너무 적습니다.

```bash
VTON_QUOTA_PER_DAY=50 VTON_QUOTA_PER_IP_DAY=500 node server/vton-proxy.mjs
```

로컬 구동이면 장당 과금이 없으므로 한도의 목적이 "비용 방어"에서 "줄 관리"로
바뀝니다.

### 개인정보 — 전시는 훨씬 가볍습니다

노트북 안에서 전부 돌면 사진이 **어디로도 가지 않습니다.** 국외이전도, 위탁도
없습니다. 그래도 관람객의 얼굴을 다루므로 최소한 이건 하세요.

- 부스에 안내문: **무엇을 촬영하고 / 어디로 가고 / 언제 사라지는가**
- "이 기기 안에서만 처리되며 저장하지 않습니다" — 지금 구조가 실제로 그렇습니다
- 결과 이미지를 나눠 준다면 그 자리에서 주고 끝내세요. 모아 두지 마세요.
- 촬영 자체를 원치 않는 분을 위해 **미리 준비한 샘플 인물**로도 볼 수 있게
  해 두면 좋습니다.

`docs/11` 의 처리방침 초안에서 "국외이전" 항목을 빼면 그대로 쓸 수 있습니다.

### 실패에 대비

전시장에서 가장 흔한 사고는 **모델 서버가 죽는 것**입니다.

지금 구조는 그때 자동으로 내장 엔진 결과로 되돌아갑니다 — 화면이 비지 않고,
관람객은 무언가를 봅니다. 이게 이 설계의 실질적인 이득입니다.

리허설에서 **일부러 모델 서버를 꺼 보세요.** 그 상태에서도 앱이 정상으로
보이는지 확인하면 당일 마음이 편합니다.
