# 7. 다각도 촬영 — 몸의 앞뒤 두께를 재다

이 도구가 스스로 적어 둔 가장 큰 한계는 이것이었습니다.

> **정면 사진 한 장에서 몸의 3D 형태를 알 수 없다.**
> 옷은 실루엣 폭에만 맞춰지며 앞뒤 두께는 반영되지 않는다.

사진을 두 장 더 받으면 이 한계가 사라집니다. 정확히는, **추정이 계산이 됩니다.**

구현은 `build/multiview.js` 이고, 그 결과를 `build/tryon.js`(원통 감기)와
`build/fitroom.js`(핏 판정·시점 전환)가 받아 씁니다.

---

## 1. 원리

몸통의 가로 단면을 생각합시다. 반폭 `a`(좌우), 반두께 `b`(앞뒤).
수직축을 중심으로 θ만큼 돌아서면 카메라가 보는 실루엣 반폭은

```
w(θ) = √( a²·cos²θ + b²·sin²θ )        (단면이 타원일 때)
```

정면(θ=0)은 `w = a` 이므로 **폭을 그대로 줍니다.** 남은 미지수는 `b`와 `θ`.

## 2. 처음에 틀렸던 접근 — 45°로 좌우

처음에는 이렇게 설계했습니다.

> 좌우로 45°씩 돌아선 두 장을 받으면, 왼쪽에서 푼 두께와 오른쪽에서 푼 두께가
> **일치해야 한다**는 조건으로 각도와 두께를 함께 풀 수 있다.

각도 탐색을 돌려 보니 추정 각도가 매번 탐색 상한(85°)에 눌러앉았습니다.
이유는 단순했습니다.

> **좌우로 똑같이 돌면, 어떤 각도를 넣어도 좌우가 똑같이 맞습니다.**

`w_L ≡ w_R` 이면 `θ_L = θ_R` 인 모든 값이 해입니다. 1-매개변수 축퇴이고,
두 사진의 일치는 각도에 대해 **아무 정보도 주지 않습니다.** 좌우 대조는
검산으로는 훌륭하지만 각도를 결정하지는 못합니다.

## 3. 실제로 쓰는 방법 — 옆모습

45°가 아니라 **옆으로 돌아선 사진**을 받습니다. θ=90°에서

```
w(90°) = b          ← 두께를 그대로 준다
dw/dθ  = 0          ← 각도 오차에 1차적으로 둔감하다
```

두 번째 성질이 결정적입니다. **완전히 90°가 아니어도 됩니다.**

| 실제 각도 | 두께 오차 |
|---|---|
| 90° | **2.7 %** |
| 80° | 3.1 % |
| 70° | 7.5 % |

각도를 정확히 맞추라고 요구하는 대신, **각도에 둔감한 지점에서 잽니다.**

### 덤 하나 — 단면 모양과 무관하다

θ=90°에서는 어떤 단면이든 `w = b` 입니다(지지함수가 같습니다).
실제로 단면을 타원이 아닌 초타원(`|x/a|^2.5 + |z/b|^2.5 = 1`, 타원보다 각진
형태)으로 그려 시험해도 두께 오차는 **2.7 %로 동일**했습니다.

> **두께 자체는 단면 가정과 무관하게 측정됩니다.**
> 타원 가정은 두께를 *둘레*로 바꿀 때만 들어옵니다.

## 4. 그러면 좌우 두 장은 왜 받는가

각도를 풀기 위해서가 아니라 **검산하기 위해서**입니다. 같은 사람의 같은
몸통이므로 왼쪽에서 잰 두께와 오른쪽에서 잰 두께는 같아야 합니다.
벌어지면 자세가 틀어졌거나 한쪽이 덜 돌아간 것이고, 그 사실을 보고합니다.

한쪽만 72°로 덜 돌린 시험에서 **좌우 편차 12 %** 가 잡혔고 신뢰도가
0.83 → 0.63으로 내려갔습니다. README가 말하는 *"정답을 몰라도 참인 성질"* 을
하나 더 얻은 셈입니다.

## 5. 덜 돌아선 사진을 잡아내기 — 머리

가장 큰 위험은 사용자가 안내를 어기고 **45°만 돌아서는** 경우입니다.
그러면 `b`가 실제보다 30~60 % 크게 나오는데, `b/a` 값만으로는 "두꺼운 사람"과
구분이 어렵습니다.

여기서 **머리**를 씁니다. 몸통의 앞뒤/좌우 비는 사람마다 크게 다르지만,
머리의 앞뒤 길이 대비 좌우 폭(두개지수)은 훨씬 좁은 범위에 있습니다(`k ≈ 1.28`).

```
w_head(θ)² = Hb²·(cos²θ + k²·sin²θ)
→ r = w_옆 / w_정면 은 90°에서 1.28, 45°에서 1.15
```

두 값이 뚜렷이 갈립니다. 시험에서 45° 컷의 머리 비는 **1.13 → "약 41°"** 로
읽혀 경고가 떴고, 90° 컷은 **1.25** 로 통과했습니다.

> **각도를 이것으로 추정하지는 않습니다.** 90° 근처에서 `sin²θ` 가 평평해
> 머리에서 나온 각도는 오차가 크고, 그 각도를 그대로 쓰면 90°로 두는 것보다
> 오히려 나빠집니다. 잡아내는 데만 씁니다.

## 6. 실측 정확도

정답을 아는 합성 인물(키 168 cm)로 측정했습니다. 비교는 **같은 물리적 높이**
에서 합니다 — 레벨 인덱스끼리 비교하면 `body.js` 의 어깨·골반 검출 오차까지
섞여 이 모듈의 기여를 알 수 없기 때문입니다.

| 조건 | 두께 오차 | 둘레 오차 (가슴/허리/골반) | 검출 |
|---|---|---|---|
| 옆모습 90° | **2.7 %** | +1.1 / +2.1 / −2.5 cm | — |
| 80° (덜 돌아섬) | 3.1 % | +1.1 / +2.1 / −3.3 cm | 통과 |
| 70° | 7.5 % | +3.5 / +4.6 / −1.7 cm | 통과 |
| 초타원 단면 | **2.7 %** (동일) | 동일 | 단면 가정 무관 |
| 좌우 비대칭(90/72°) | 3.3 % | — | **좌우 편차 12 % 감지** |
| 45°만 돌아섬 | 큼 | 큼 | **머리 비로 감지 → 경고** |

## 7. 잰 값으로 무엇이 달라지는가

### (가) 옷이 몸을 감싼다 — 원통 감기

전에는 옷본의 가로 좌표를 실루엣 폭에 **선형으로** 폈습니다. 그러면 옷이
몸을 감싸는 게 아니라 앞에 납작하게 붙습니다. 표면의 각위치 φ로 다시 배치하면

```
X(φ) = a·sinφ·cosθ + b·cosφ·sinθ = R·sin(φ + δ)
δ    = atan2(b·sinθ, a·cosθ)
→ φ  = asin(t) − δ          (t = 실루엣 안의 정규화 위치)
```

옆으로 갈수록 천이 급격히 줄어들어, 몸통이 원기둥으로 보입니다.
`b/a` 는 **잰 값**을 씁니다. 옆모습이 없으면 0.72를 쓰되 화면에
*"표준 비율로 가정했습니다"* 라고 밝힙니다.

`|φ| > 90°` 는 옷본에 없는 뒷면입니다. 접어서 되비추면(중앙 앞섶이 중앙 뒤로
갑니다) 대칭 의류에서는 자연스럽게 이어집니다.

### (나) 세 시점 모두에 입혀 본다

정면·왼쪽·오른쪽 각각에 같은 착장을 합성하고, 시점 버튼으로 전환합니다.
각 시점의 요 각도가 위 식에 들어가므로 옆에서는 옷도 옆모습으로 감깁니다.

### (다) 핏을 cm로 말한다

폭만 알 때는 "커 보인다/작아 보인다"밖에 말할 수 없었습니다. 둘레를 알면
여유분을 cm로 말할 수 있습니다.

```
작습니다 (≤ −2cm) · 딱 맞습니다 (≤ 4) · 적당합니다 (≤ 12)
· 여유롭습니다 (≤ 22) · 많이 큽니다
```

**이 값을 두 번 틀렸습니다.** 기록해 둡니다.

1. *"평평하게 편 옷의 폭 = 둘레의 절반"* 으로 계산 → 티셔츠가 **−13 cm**.
   우리 옷본의 반폭은 평평하게 편 폭이 아니라 **투영 반폭**이었습니다.
2. 화면에 그려진 앵커 폭에서 역산 → 이번엔 모든 옷이 작게 나왔습니다.
   렌더는 체형을 0.6제곱으로 **감쇠해서** 따라갑니다(그래야 자연스럽습니다).
   보기 좋으라고 넣은 감쇠를 치수 계산에 끌어다 쓴 것이 잘못이었습니다.

지금은 렌더가 아니라 **옷이 선언한 치수감**에서 계산합니다. 카탈로그의
`fit` 은 표준 핏 1.00 기준의 상대 치수이고, 표준 핏의 여유분은 대략 8 cm 입니다.
몸 둘레는 옆모습에서 잰 값이므로, 이 판정은 *"이 컷의 옷을 당신의 실측 몸에
대면 얼마가 남는가"* 가 됩니다.

> 사용자가 넣은 **실제 옷 사진은 치수를 알 수 없으므로 핏을 판정하지 않습니다.**
> 사진에서 옷의 실제 크기를 읽을 방법이 없고, 지어내지 않습니다.

### (라) 폭의 기준자가 하나로 통일된다

`body.js` 의 랜드마크 폭은 "어깨~허리 사이 최대 폭"이라 팔이 몸에 닿으면
부풀어 오릅니다. `multiview` 쪽은 분위수로 그 오염을 걷어낸 값입니다.
두 값이 다르면 **옷 둘레와 몸 둘레가 다른 자로 재져** 핏 판정이 틀어집니다
(티셔츠가 실제보다 20 % 크게 나왔습니다). 옆모습이 있으면 옷의 앵커도
`multiview` 프로파일을 쓰도록 통일했습니다.

## 8. 구현하며 잡은 조용한 버그들

| 증상 | 원인 |
|---|---|
| 각도가 항상 탐색 하한(12°)에 붙고 결과가 NaN | `body.js` 행 필드는 `coreX0/coreX1` 인데 `cx0/cx1`(tryon 쪽 이름)로 읽었다 |
| 머리 폭이 키의 20 %(=어깨 폭)로 측정됨 | 창을 턱 위치 기준으로 잡았는데, 얼굴 검출이 빗나가면 창이 어깨까지 내려간다 → 키 대비 고정 구간으로 교체 |
| 골반 둘레가 11 cm 과소평가 | 샘플 창이 골반선 아래로 넘어가 **다리 한 짝**을 몸통으로 읽었다 |
| 옆모습에서만 `rows[y]` 가 undefined | `saneLM` 의 clamp 경계가 소수라 랜드마크가 소수로 나왔다. 정면에서는 clamp가 걸리지 않아 드러나지 않았다 |
| 슬림 티셔츠와 오버핏 후디가 같은 폭으로 그려짐 | 옷본 중앙값으로 나누면서 옷본에 들어 있던 `fit` 계수가 약분됐다 |

## 9. 정직한 한계

- **두께는 잽니다. 둘레는 환산합니다.** 단면이 타원이라는 가정이 들어가며,
  실제 허리 단면은 타원보다 각져 있어 타원 둘레는 대체로 **작게** 나옵니다.
  줄자 실측을 한 곳만 넣으면 그 비율로 나머지를 보정합니다 — 편차는 사람마다
  다르지만 **한 사람 안에서는 높이별로 비슷하기** 때문입니다.
- **옷 두께가 그대로 더해집니다.** 사진 속 몸 둘레에는 그때 입고 있던 옷이
  포함됩니다. 몸에 붙는 옷일수록 정확합니다.
- **키가 없으면 cm를 만들지 않습니다.** 두께 *비율* 은 키 없이도 측정되지만,
  둘레를 cm로 내려면 기준자가 필요합니다. 없는 근거로 숫자를 찍어내지 않습니다.
- **옆모습에서 팔이 몸통 앞뒤로 튀어나오면 두께가 부풀어 오릅니다.**
  팔은 몸의 옆에 달려 있어 옆에서 보면 대체로 몸통에 가려지지만, 손이 앞으로
  나오면 그만큼 더해집니다.
- **인물 분리가 실패하면 이 측정도 실패합니다.** 단색 배경에서 가장 정확합니다.
