# 6. 가상 피팅 — 실제 옷 이미지를 실제 사람 사진에 입히는 방법

이 문서는 네 가지 질문에 답합니다.

1. 어떤 원리로 실제 사람 사진에 실제 옷 이미지를 넣는가
2. 옷 이미지 데이터베이스를 어떻게 확보하는가
3. 색을 AI로 바꾸는 방법은 무엇인가
4. 그것을 HTML 한 개로 어떻게 구성하는가

구현은 `build/garments.js` · `build/recolor.js` · `build/tryon.js` ·
`build/fitroom.js` 에 있고, `build/build.py` 가 이들을 `퍼스널컬러진단.html`
안으로 합칩니다.

---

## 1. 원리 — 상용 가상 피팅은 무엇을 하는가

이미지 기반 가상 피팅(image-based virtual try-on)의 표준 파이프라인은
VITON → CP-VTON → VITON-HD → IDM-VTON 계열로 이어지며, 네 단계로
정리됩니다.

```
① 사람에게서 옷을 지운다   clothing-agnostic person representation
② 옷을 몸에 맞게 변형한다   TPS warping / appearance flow
③ 변형된 옷을 합성한다     composition
④ 경계와 질감을 다듬는다   GAN · diffusion refinement
```

### ① 옷을 지운다

원본 사진에서 **기존 의류 영역을 제거**하고 그 자리를 비웁니다. 이 단계가
없으면 새 옷이 원래 옷보다 짧거나 좁을 때 옛 옷이 삐져나옵니다.
연구 코드는 사람 파싱(human parsing) 모델의 세그먼트 맵을 써서 상의 영역만
정확히 지웁니다.

### ② 옷을 변형한다

납작한 상품컷을 몸의 자세에 맞게 휘게 만드는 단계입니다. 두 계열이 있습니다.

- **TPS(Thin-Plate Spline)** — 대응점 몇 쌍을 주면 그 사이를 *휘어짐 에너지가
  최소가 되도록* 매끄럽게 잇는 고전적 보간법. CP-VTON이 이 방식입니다.
  가볍고 설명 가능하지만, 대응이 크게 비선형이면 지도가 접힙니다.
- **Appearance flow** — 픽셀마다 이동 벡터를 신경망이 직접 예측. 훨씬
  유연하지만 학습된 모델이 필요합니다.

### ③ 합성 · ④ 다듬기

변형한 옷을 비워둔 자리에 얹고, 경계·그림자·가려짐(팔이 몸 앞에 오는 등)을
생성 모델이 정리합니다. **④가 GPU 서버와 수 GB 가중치를 요구하는 유일한
단계**입니다.

### 이 도구가 택한 것

①②③을 그대로 구현하고, ④만 **물리적 근거로 대체**했습니다.

> 이 프로젝트의 첫 번째 약속은 "사진이 브라우저 밖으로 나가지 않는다"입니다.
> ④를 넣으려면 사진을 서버로 보내야 하고, 그 순간 약속이 깨집니다.
> README의 *P1 검출 개선*에서 모델 도입을 미룬 것과 같은 판단입니다.

생성 모델 없이 합성이 "붙여넣기"로 보이지 않게 하는 것은 결국 **빛**입니다.
그래서 사진에서 조명장을 뽑아 옷에 다시 씌웁니다 — 이 한 가지의 유무가
가장 큰 차이를 만듭니다.

```
사진 → 크게 흐림 → 조명장 L(x,y)
옷 픽셀 × (1 + (L/L̄ − 1) · α)      α = 빛 이식 슬라이더 (기본 0.75)
```

왼쪽에서 빛이 든 사진이면 옷의 왼쪽도 밝아집니다.

## 2. 구현에서 실제로 배운 것 — 세 번의 실패

TPS는 교과서적이지만, **틀려도 오류를 내지 않고 조용히 이상한 그림을
내놓습니다.** 그래서 매 단계를 수치로 재면서 고쳤습니다. 세 가지가
결정적이었습니다.

### (가) 선형계를 파괴적으로 풀고 재사용했다

```js
// 잘못
var wx = gauss(A, bx, m), wy = gauss(cloneMat(A, m), by, m);
```

`gauss()`는 A를 소거하며 파괴합니다. 자바스크립트는 왼쪽부터 평가하므로
두 번째 `cloneMat`은 **이미 소거된** A를 복사했습니다. 결과적으로
x 매핑은 멀쩡하고 **y 매핑만 쓰레기**가 됩니다.

| 지표 | 수정 전 | 수정 후 |
|---|---|---|
| 중심선 매핑의 비단조 구간 (38 표본) | **20** | **0** |
| 몸통 픽셀이 옷 밖으로 날아간 비율 | **67.9 %** | **2.8 %** |
| 상의 한 벌의 덮은 픽셀 | 18,173 | **54,987** |

가슴 한복판에 뚫린 구멍의 정체가 이것이었습니다.

### (나) 옷본과 몸의 세로 비율이 어긋났다

옷본의 소맷부리는 캔버스의 61.5 % 지점, 밑단은 86 % 지점에 있었습니다.
그런데 몸에서 계산한 손목은 밑단보다 **아래**였습니다. TPS는 옷의 172 px
구간을 몸의 24 px 안에 욱여넣어야 했고, 소매가 말려 접혔습니다.

해법은 **하나의 해부학 사다리를 양쪽이 공유**하는 것입니다.

```
어깨 .085 · 겨드랑이 .232 · 허리 .432 · 골반 .593 · 손목 .784
밑단: 크롭 .335 · 허리 .445 · 힙 .633 · 허벅지 .772 · 무릎 .950
```

`garments.js`의 `HEM_Y`와 `tryon.js`의 `HEM_BODY`가 같은 지점을 가리킵니다.
나아가 상의는 **어깨선과 밑단만 몸에서 정하고, 그 사이의 모든 지점은
옷본의 비율 그대로** 배치합니다 — 정의상 순서가 뒤집힐 수 없습니다.

### (다) 하나의 지도로 몸통과 소매를 함께 변형했다

옷본에서 소매는 몸통 옆에 붙어 아래로 뻗지만, 사진 속 팔은 각도도 굵기도
제각각입니다. 두 배치를 하나의 매끄러운 변형으로 이을 수 없어 지도가
접힙니다(non-injective).

그래서 **부위별 워핑(part-based warping)** 으로 나눴습니다.

```
상의   몸통(12점+중점 6) · 왼소매(6점) · 오른소매(6점)
바지   엉덩이 블록 · 왼다리(6점) · 오른다리(6점)
```

조각마다 대응이 거의 아핀에 가까워져 접힘이 사라집니다. 바지를 나누지
않았을 때는 두 다리가 한 덩어리로 붙어 **치마처럼** 보였습니다.

여기에 두 가지 규칙을 덧붙였습니다.

- **소매는 엄격하게, 몸통은 관대하게.** 소매는 옷본의 소매 영역에 제대로
  떨어진 픽셀만 그립니다(정확도 우선). 몸통은 옷본 폭 바깥으로 나간 좌표를
  버리지 않고 **잘라서** 읽습니다 — 버리면 그 자리가 구멍으로 남습니다.
- **몸통에는 몸 쪽 울타리도 친다.** 몸통이 관대해진 대신, 팔뚝처럼 몸통
  바깥이면서 인물 안쪽인 자리에 몸통 천이 얹히는 일이 생겼습니다
  (손목에 천 조각이 붙은 것처럼 보였습니다).

### 그 밖에 수치로 잡은 것들

| 증상 | 원인 | 조치 |
|---|---|---|
| 중앙이 부풀어 가슴이 밖으로 밀림 | 대응점이 전부 좌우 끝에만 있음 | 좌우 중점을 대응점으로 추가 |
| 가슴에 구멍 (다른 원인) | 몸의 어깨 폭(팔 포함)이 옷본과 **반대 방향**으로 변함 | 폭의 순서는 옷본이 정하고 체형은 감쇠(0.6제곱)해서 섞음 |
| 다리가 허옇게 뜸 | 확산 채우기의 출처에 **배경**이 포함됨 | 출처를 인물 안쪽으로 제한 |
| 옷 전체가 뿌옇게 흐려짐 | 경계 블러를 옷 전체에 적용 | 피부로 칠한 자리만 블러 |
| 손목에 천 조각 | 소맷부리 아래로 외삽된 좌표가 다시 소매로 떨어짐 | 소매 조각에 상한 추가 |
| 해가 진동 | 픽셀 좌표를 그대로 TPS에 투입(조건수 폭발) | 무게중심·평균반경으로 정규화 |
| 목선 위에 옛 옷깃이 남음 | 지우기 밴드가 어깨선부터 시작 | 목 밑동까지 올림 |

## 3. 옷 이미지 데이터베이스

### 왜 실제 상품컷을 담을 수 없는가

기술이 아니라 **권리** 때문입니다.

- 쇼핑몰 상품컷은 전부 저작물입니다.
- 공개 데이터셋(VITON-HD · DressCode · DeepFashion)은 **연구 목적 라이선스**라
  배포본에 담을 수 없습니다.

그렇다고 벡터 일러스트로 대체하면 "옷을 입어봤다"는 느낌이 나오지 않습니다.
사람이 옷을 사진으로 인식하는 근거는 실루엣이 아니라 **직물의 결과 주름
음영**이기 때문입니다.

### 그래서: 옷을 그리지 않고 합성한다

```
실루엣(옷본) + 소재별 직조 텍스처 + 드레이프 주름 + 가장자리 AO
+ 원통 볼륨 + 정반사 + 봉제선·단추·리브  →  알파를 가진 RGBA 래스터
```

소재는 색이 아니라 **결**로 구분됩니다.

| 소재 | 직조 표현 |
|---|---|
| 데님 | 능직 대각선 + 씨실 슬럽 |
| 니트 | 굵은 세로 리브 + 얕은 가로 코 |
| 코듀로이 | 굵은 세로 골(wale) |
| 린넨 | 가로세로 교차 + 강한 불규칙 |
| 트위드 | 높은 고주파 얼룩 |
| 새틴/실크 | 매끈한 면 + 넓은 정반사 대역 |
| 레더 | 셀 노이즈 + 강한 정반사 |

주름은 어깨(또는 허리)에서 방사되며 아래로 갈수록 간격이 벌어지고 깊어집니다.
위상에 노이즈를 섞지 않으면 커튼처럼 규칙적으로 보입니다. 시드는 옷 id에서
뽑으므로 **같은 옷은 항상 같은 결**로 나옵니다.

현재 카탈로그는 **8개 스타일 × 4개 부위 = 45벌**입니다.

```
미니멀 · 캐주얼 · 오피스 · 스트릿 · 로맨틱 · 스포티 · 클래식 · 시크
상의 16 · 아우터 10 · 하의 12 · 원피스 5
```

### 실제 옷 사진은 사용자가 넣는다

`내 옷 사진 추가` → 배경 자동 제거 → **옷본 수치 자동 측정** → 손으로 보정 →
IndexedDB 저장. **한 번 넣은 옷은 다음에 열어도 남아 있습니다.**

상품 사진이든 생성형 AI가 만들어 준 그림이든, **평면으로 펼쳐 놓고 정면에서
찍힌 옷**이면 같은 경로로 들어옵니다.

배경 제거는 테두리에서 배경색을 학습하되 **테두리에서 연결된 영역만**
지웁니다. 연결성을 보지 않으면 흰 셔츠의 몸통이 통째로 날아갑니다.

#### 사진에서 재는 것과, 재지 않고 가져오는 것

이 도구의 옷본은 그림이 아니라 **숫자 한 벌**입니다 — 어깨 너비, 겨드랑이
높이, 몸통·허리·밑단 폭, 소매 끝 위치, 목선. 절차적 카탈로그는 이 숫자를
설계로 정하고, 반입한 사진은 실루엣에서 **재서** 채웁니다. 그 뒤는 완전히
같은 코드입니다.

가장 중요한 것은 **겨드랑이**입니다. 소매가 몸통에서 갈라지는 지점 아래로는
소매와 몸통 사이로 배경이 쐐기처럼 들어옵니다 — 한 행에 구간이 둘 이상
생깁니다. 그 쐐기의 꼭짓점이 곧 겨드랑이입니다. 추정할 필요가 없습니다.

기장은 **길이 ÷ 폭**으로 판정합니다. 사진에는 "이 옷이 몸의 어디까지
오는가"가 적혀 있지 않지만, 어깨 너비 대비 길이(상의)와 골반 너비 대비
길이(하의)는 기장마다 확연히 다릅니다. 판정하지 않으면 하의가 기본값
`knee`로 떨어져 **긴 바지가 무릎에서 잘린 채로** 입혀집니다.

실루엣이 알려주지 않는 값 — 소맷부리 안쪽 모서리처럼 윤곽선이 거의 한
점으로 만나는 자리 — 은 **같은 소매 종류의 옷본 비율**을 씁니다. 재서 알
수 있는 것과 없는 것을 섞지 않습니다.

앵커 자동 측정은 **초안**이며 드래그로 고칠 수 있습니다. 이 도구가 얼굴
측정점과 체형 가이드에서 취한 태도와 같습니다.

#### 사진 반입이 요구하는 조건

| 조건 | 왜 |
|---|---|
| 옷을 **펼쳐 놓은** 사진 | 접히거나 모델이 입은 사진은 폭이 실제 옷본이 아니다 |
| **정면** · 기울지 않게 | 좌우 대칭을 전제로 대응점을 만든다 |
| 단색 배경 | 배경 제거가 연결성에 기댄다 |
| 그림자 없이 | 바닥 그림자는 옷의 일부로 잡힌다 |
| 소매를 **몸통에서 떼어** 펼치기 | 겨드랑이는 소매·몸통 사이의 틈으로 찾는다 |

마지막 줄이 실패하면 소매가 없는 옷(`sleeve: 'none'`)으로 판정되어 소매가
몸통 요크에 묻힙니다 — 터지지는 않지만 팔이 제대로 덮이지 않습니다.

> 반입한 사진은 픽셀째로 이 브라우저에만 저장되며 어디로도 전송되지 않습니다.

## 4. 색을 AI로 바꾸는 방법

"AI로 색을 바꾼다"에는 두 가지가 섞여 있습니다.

| | 방식 | 품질 | 대가 |
|---|---|---|---|
| **A** | 확산 모델이 옷을 다시 그린다 | 가장 좋음 | GPU 서버 · 수 GB 가중치 · **사진 업로드** |
| **B** | 픽셀을 조명 성분과 색 성분으로 **분해**해 색만 교체 | 좋음 | 브라우저에서 ~100 ms |

이 도구는 **B**입니다. B를 단순한 색조 덮어쓰기와 구별짓는 것은 다음
다섯 가지이며, 이것이 없으면 옷이 아니라 색종이가 됩니다.

### ① 음영 보존

픽셀의 밝기는 `옷 색 × 그 지점에 닿은 빛`입니다. 비율만 남기고 기준 밝기를
갈아끼우면 주름이 살아 있습니다.

```
s      = (L + 4) / (L̄ + 4)          ← +4는 앰비언트 바닥값(검정 옷 보호)
L_new  = (L_target + 4) · s^γ − 4     γ는 소재별 (니트 1.12 … 실크 0.86)
```

### ② 채도 곡선

실제 직물은 깊은 그늘과 하이라이트에서 채도가 떨어집니다. 전 픽셀에 같은
채도를 칠하면 플라스틱처럼 보입니다.

문턱값은 **고정값이 아니라 그 옷감의 실제 음영 분포(군집 상·하위 10 %)** 에
맞춥니다. 고정값을 쓰면 음영 폭이 넓은 옷감(가죽·새틴)에서 평범한 밝은 면까지
하이라이트로 분류돼 채도가 깎입니다 — 검은 라이더재킷을 색만 바꿨을 때
옆구리에 **창백한 띠**가 생긴 원인이었습니다.

### ③ 정반사는 더한다 (이색성 반사 모델)

보이는 빛 = 확산 + 정반사이고, 정반사는 표면색과 무관하게 **더해지는**
성분입니다.

처음에는 하이라이트를 원본 밝기 쪽으로 *섞어서* 보존했습니다. 그러면 검은
가죽재킷을 크림색으로 바꿀 때 하이라이트가 원본의 **어두운** 값으로 끌려가
광택이 얼룩이 됩니다(질감 보존 0.38로 측정). 확산 성분을 넘어선 초과분만
떼어내 새 색 위에 얹으면 밝은 옷에서도 어두운 옷에서도 맞습니다.

### ④ 군집 분리 — 그리고 병합

스트라이프·프린트는 색이 여러 개입니다. 하나만 바꾸고 나머지는 그대로 둬야
무늬가 살아남습니다.

군집화는 **명도 가중치를 0.3으로 낮춘 Lab 공간**에서 합니다. 그냥 Lab에서
나누면 같은 파란 옷의 밝은 면과 그늘진 면이 서로 다른 색으로 갈라집니다.

그것만으로는 부족해서 **넉넉히 나눈 뒤 병합**합니다. 색상면(a,b)에서 가까운
군집은 명도가 달라도 같은 색으로 봅니다.

> 병합 전에는 단색 셔츠가 3개 군집으로 쪼개져 "가장 넓은 군집"만 바뀌었고,
> 목표색 오차가 **ΔE 37.4** 였습니다. 병합 후 군집 1개, **ΔE 0.85**.

### ⑤ 양 끝은 자르지 않고 눌러 담는다

검은 가죽(L≈16)을 크림색(L≈91)으로 바꾸면 하이라이트가 갈 자리가 9밖에
없습니다. 그대로 두면 L=100에 걸려 잘리고 광택이 납작한 흰 덩어리가 됩니다.
무릎(knee) 위에서만 로그처럼 압축하면 계조가 남습니다.

> 전체 감마를 낮추는 방법도 시도했지만 여유가 충분한 옷까지 납작해져
> 폐기했습니다. 문제는 범위 전체가 아니라 양 끝입니다.

### 결과를 되잰다

변환이 실제로 얼마나 먹혔는지 화면에 그대로 보고합니다.

| 표시 | 뜻 |
|---|---|
| **목표색 오차 ΔE** | 요청한 색과 실제로 나온 평균색의 거리 |
| **질감 보존 %** | 변환 뒤에도 주름의 명암 폭이 얼마나 남았는가 (상대 대비 비) |

질감 보존은 **절대 표준편차가 아니라 평균 밝기로 나눈 상대 대비**로 잽니다.
절대값으로 재면 밝은 옷을 어두운 색으로 바꿀 때 항상 낮게 나오는데, 어두운
천의 절대 광량 변화가 작은 것은 물리적으로 옳은 일이지 주름이 사라진 것이
아닙니다.

> 검은 가죽을 크림색으로 바꾸면 질감 보존이 0.23까지 떨어집니다.
> **이것은 실패가 아니라 물리입니다** — 밝은 천은 어두운 천보다 절대 광량
> 변화가 작습니다. 숨기지 않고 그대로 표시합니다.

### 왜 이것을 "AI"라 부르는 데 조심하는가

여기에는 학습된 모델이 없습니다. 색 과학과 반사 모델에 기반한 **설명 가능한
연산**입니다. README의 *"블랙박스를 쓰지 않는다"* 와 같은 태도이며, 그래서
어떤 값이 왜 그렇게 나왔는지 화면에서 근거를 댈 수 있습니다.

확산 모델을 쓰고 싶다면 필요한 것은 코드가 아니라 **결정**입니다 —
사진을 서버로 보내도 되는가. 그 결정을 내린 뒤에 할 일입니다.

## 5. HTML 한 개로 구성하는 법

배포 형태는 **더블클릭으로 열리는 HTML 한 개**입니다. 새 기능도 같은 파일
안으로 들어가야 합니다. 그렇다고 600 KB짜리 HTML을 직접 편집하면 모듈 경계가
사라지므로, 모듈은 따로 두고 빌드 시점에 합칩니다.

```
build/base.html      손대지 않은 원본 (가상 피팅 이전 상태)
build/garments.js    옷 데이터베이스 · 절차적 렌더 · 사진 반입
build/recolor.js     소재 인식 색 변환
build/tryon.js       TPS 워핑 · 가림 · 조명 이식 · 지우기
build/fitroom.js     화면
build/fitroom.css    스타일
        │  python3 build/build.py
        ▼
퍼스널컬러진단.html
```

원본을 그대로 두는 이유: 어떤 변경이 이 기능 때문에 생긴 것인지
`diff build/base.html 퍼스널컬러진단.html` 한 줄로 확인할 수 있습니다.
빌드 스크립트는 앵커 문자열이 정확히 한 번 나타나는지 검사하고, 아니면
**실패합니다** — 원본이 바뀌었는데 조용히 잘못 합쳐지는 일을 막습니다.

### 기존 구조에 얹는 방법

전부 기존 관습을 그대로 따릅니다.

- 모듈은 IIFE로 감싸 전역에 하나의 이름만 노출 (`GARMENTS` · `RECOLOR` ·
  `TRYON` · `FITROOM`) — 기존 `CC` · `DETECT` · `BODY`와 같은 방식
- 스크립트 순서: 엔진 3종은 `BODY` 뒤 · `RECOMMEND` 앞, 화면은 `REPORT` 뒤
- 리포트에 `가상 피팅` 탭 추가 (코디 바로 다음)
- CSS는 기존 디자인 토큰(`--blue` · `--fill-3` · `--r-box` …)만 사용

### 성능 — 브라우저에서 돌리기 위한 것들

| 기법 | 효과 |
|---|---|
| 탭을 실제로 열 때 준비 시작 | 리포트 렌더가 늦어지지 않음 |
| 색 변환 결과 LRU 캐시(24개) | 슬라이더 조작 시 재합성 **약 300 ms → 110 ms** |
| TPS를 5 px 격자에서만 풀고 이중선형 보간 | 픽셀마다 푸는 것보다 ~10배 |
| 썸네일은 1/5 해상도 + IntersectionObserver | 45벌 목록이 즉시 뜸 (한 장 ~7 ms) |
| `allow` 마스크를 반경별 캐시 | 슬라이더 중 반복 팽창 제거 |

한 벌 합성 평균 **107 ms** (420×900, 45벌 × 체형 3종 = 129회 측정).

### 검증

```bash
node build/test-tryon.mjs          # 엔진 파이프라인 + 워핑 품질 지표
node build/test-ui.mjs             # 실제 브라우저에서 화면 조작
node build/test-all.mjs            # 45벌 × 체형 3종 = 129회 합성
node build/test-recolor-visual.mjs # 색 변환 격자 이미지
```

현재 **합성 실패 0건 · 페이지 오류 0건**입니다.

## 6. 이 기능의 정확한 포지션

README의 표에 한 줄을 더한다면 이렇습니다.

| 영역 | 실용성 | 신뢰도 |
|---|---|---|
| 색을 내 몸에서 확인하기 | 높음 | — (도구이지 판정이 아님) |
| 실루엣·기장 감 잡기 | 중간 | 낮음~중간 |
| 실제 착용 모습 재현 | 낮음 | **낮음** |

### 할 수 없는 것

- **정면 사진 한 장에서 몸의 앞뒤 두께를 알 수 없습니다.** 옷은 실루엣 폭에만
  맞춰집니다. 체형 분석이 "핏 성향 추정"에 그치는 것과 같은 한계입니다.
- **원래 옷이 새 옷보다 크면 드러나는 부분을 복원할 수 없습니다.** 주변 색으로
  메우고 그 면적을 화면에 보고합니다.
- **팔짱·주머니에 넣은 손처럼 복잡한 가림은 처리하지 못합니다.**
- **인물 분리가 실패하면 피팅도 실패합니다.** 단색 배경에서 가장 정확합니다.
  옷과 배경의 색이 비슷한 경우(흰옷 + 흰벽)는 배경 자신의 산포로 임계를
  잡아 IoU 0.33 → 0.86까지 끌어올렸지만, 배경이 인물과 같은 색이고 그
  면적까지 넓으면 구분할 신호 자체가 없습니다 —
  [8. 인물 분리와 랜드마크](08_인물_분리와_랜드마크.md) 참고.

### 드러난 부분을 채우는 두 가지 방식

같은 "빈자리"라도 성격이 다릅니다.

| 종류 | 아는가 | 처리 |
|---|---|---|
| 새 옷의 밑단 아래 다리, 소매끝 아래 팔 | **안다** — 이 사람의 피부다 | 얼굴에서 잰 피부색 × 그 자리의 빛 |
| 옷 경계의 자투리 | **모른다** | 주변 색 확산 · 면적을 보고 |

피부로 그린 부분은 **실제 팔·다리의 음영이나 형태가 아니라는 경고를 함께**
띄웁니다.

이 기능은 *"이 색과 이 실루엣이 나에게 어떻게 보이는가"* 를 위한 것이지
상품 상세컷을 만들기 위한 것이 아닙니다.
